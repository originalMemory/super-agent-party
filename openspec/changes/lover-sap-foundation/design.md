## 目标陈述（已定稿方向）

**lover** 为自 SAP **硬分叉**的独立产品线：**唯一代码路径**，**无 `loverMode`**，**不保留**酒馆式旧页面与并行逻辑。单一用户与 **唯一 Agent**；人设与纪律来自 **`.agent/` Markdown SSOT**。  
人设注入：**会话常驻一份 bootstrap**：**用户档案 + 完整初始角色信息**（叙事设定与运行纪律一并注入，**不设**酒馆式设定书或关键词按需拼装）。**每轮 FTS 仅检索「记忆」Markdown**（`MEMORY.md`、按日日记等），**不得**索引人设文件。分词器倾向 **[wangfenjin/simple](https://github.com/wangfenjin/simple)**。向量 mem0 是否保留以实现为准。  
会话形态：**主会话 + 归档**，支持 **主动归档** 与 **重置会话**。

**品牌与仓库命名**：后续对外将 **super-agent-party** 更名为 **super-agent-lover**（仓库名、包名、文档标题等与发布节奏对齐）。

## OpenClaw 对齐：`USER.md` / `IDENTITY.md` / `SOUL.md` 是否要合并？

与你当前 OpenClaw 工作区（如 `openclaw-data/workspace`）用法对照：

| 文件 | 实际承担（你的现状） | 合并建议 |
|------|----------------------|----------|
| **`USER.md`** | **人类用户**的事实与偏好（姓名、作息、关系定义里「幻灭」一侧等） | **建议始终独立**：与用户档案编辑频率、隐私边界一致；**不宜**与 Agent 叙事拧在一个文件里。 |
| **`IDENTITY.md`** | Agent **叙事内身份**：外貌、人设性格、相处方式等（「焰」是谁） | 可与 SOUL **择一维护策略**：要么 **两个文件**（叙事 vs 元纪律分层清晰），要么 **合并为一个文件两个顶级章节**（见下）。 |
| **`SOUL.md`** | **元层伴侣纪律**：反机械回复、主动性、记忆文件约定、边界等（「怎么当人而不是搜索引擎」） | 与 IDENTITY 在「氛围/性格」上有重叠属正常；**职能上**仍是「运行原则」≠「外貌与设定书」。 |

**结论**

1. **不必为三选一硬合并成一个文件**。沿用 **USER + IDENTITY + SOUL** 三等分与 OpenClaw 实践一致，也最利于「改用户事实不改人设」「改原则不改外貌」。  
2. **不要为了合并而合并 USER**：USER 与人设混写会降低可读性与权限心智（哪些是给模型看的「用户设定」、哪些是角色）。  
3. **若只想减少文件数**：优先 **合并 IDENTITY + SOUL** → 例如单一 **`IDENTITY.md`**（或 Rename 为 `CHARACTER.md`），内分：
   - `## 角色与叙事`（原 IDENTITY 主体）
   - `## 原则与运行方式`（原 SOUL 主体）  
   **USER.md 仍单独保留**。合并后删掉独立 `SOUL.md`，并在 README 写明一节对应关系，避免双注入。

**AGENTS.md**（可选）：工具/协作元指令；与「伴侣人设」分离；有 CLI/工具链时建议保留，见下表。

| 文件 | lover 建议 |
|------|------------|
| **`MEMORY.md`** | **必需**（路径以实现为准）。**仅**纳入 FTS。 |
| **`USER.md`** | **必需**（单一用户产品）；bootstrap，不进 FTS。 |
| **`IDENTITY.md`** | **与 SOUL 二选一呈现**：要么保留独立文件，要么合并进带章节的单文件。 |
| **`SOUL.md`** | **与 IDENTITY 二选一呈现**：同上；合并则删除冗余重复段落。 |
| **`AGENTS.md`** | 可选；有工具则 bootstrap 靠前加载。 |

**Bootstrap 注入顺序（建议）**：`AGENTS`（若有）→ `USER` → `IDENTITY`（若合并则含原 SOUL 章节）→ `SOUL`（若仍为独立文件）→ **不得**再单独走设定书/关键词分支。

## 设计原则

1. **单一产品**：无模式开关；移除酒馆 UI 与角色卡主导航。
2. **Markdown SSOT**：bootstrap 集合与加载顺序固定并文档化。
3. **人设 vs 记忆**：**完整初始角色信息（含原设定书内容）** 在 **会话锚点一次性注入**（可多文件拼接）；**仅记忆语料**走 **每轮 FTS**。
4. **mem0**（若启用）：唯一 Agent id。
5. **主会话 + 归档**。
6. **分叉与上游**：择优合并 SAP。

## MVP 边界

### 纳入

- SSOT 完整 bootstrap（USER + IDENTITY/SOUL 按仓库约定）。
- **记忆 FTS**（simple）+ 每轮注入。
- 主会话、归档、主动归档、重置。
- 移除酒馆路径。

### 首期非目标

- OpenClaw 同款 QMD。
- 完整桌面主动感知（backlog）。

### 记忆索引范围

至少 **`MEMORY.md`** + 按日日记路径。**不得**将 USER / IDENTITY / SOUL / AGENTS 纳入默认 FTS。
